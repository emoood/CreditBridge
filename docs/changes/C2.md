  - `id` (Integer, PK)
  - `app_id` (ForeignKey to applications.id, indexed)
  - `recipient` (String)
  - `original_recipient` (String)
  - `subject` (String)
  - `body` (Text)
  - `items` (JSON list of request item dictionaries)
  - `status` (String: `SENT`, `SIMULATED`, `FAILED`)
  - `error` (Text)
  - `simulated` (Boolean)
  - `sent_at` (DateTime with timezone)
- **RowState.requests**: Added support for request item types (`syllabus or outline`, `exam score report`, `official transcript with credits`, `translation`, `other`) and secure one-time upload `token`.

## 5. API Endpoints
- `GET /api/v1/applications/{app_id}/requests`: Lists all open and closed requests across rows for a student.
- `POST /api/v1/applications/{app_id}/rows/{row_id}/requests`: Admissions officer adds a request item.
- `DELETE /api/v1/applications/{app_id}/rows/{row_id}/requests/{request_id}`: Admissions officer removes a request item.
- `PATCH /api/v1/applications/{app_id}/rows/{row_id}/requests/{request_id}`: Admissions officer edits request text or type.
- `GET /api/v1/applications/{app_id}/outbox/preview`: Generates single grouped email preview for applicant.
- `POST /api/v1/applications/{app_id}/outbox/send`: Admissions officer triggers email sending (SMTP or simulated).
- `GET /api/v1/applications/{app_id}/outbox`: Retrieves outbox delivery log for student.
- `POST /api/v1/reply`: Secure student document upload using one-time token; marks item `RECEIVED` and enqueues single-row resume job.
- `GET /api/v1/reply/{token}`: Validates token and returns request details for upload portal.
- `POST /api/v1/applications/{app_id}/rows/{row_id}/syllabus-compare`: Runs syllabus comparison against target AUD course.
- `POST /api/v1/applications/{app_id}/rows/{row_id}/syllabus-review`: Officer accepts or rejects proposal; optionally writes versioned row to `course_mappings`.

## 6. How It Works (Flow)
1. Requests are drafted either by the Case agent during evaluation or by an officer in `StudentPopup` / `OutboxModal`.
2. Requests are stored per-row in `RowState.requests` with normalized types and upload tokens.
3. When officer views the Outbox, uild_email_content compiles one grouped email with greeting, requirements checklist, upload link, deadline, and signature. Recipient email is automatically loaded from the application extraction student record or can be entered/overridden directly in the Outbox modal by the admissions officer.
4. Clicking Send invokes send_student_email. If EMAIL_SENDING is false, it logs a SIMULATED outbox record. If true, it enforces allowlists, redirects .invalid demo addresses to the test inbox, and sends via SMTP. Open items transition to SENT. If an email was missing from the record and supplied by the officer, it is saved on the application extraction for future correspondence.
5. When a document is submitted via `/reply` with the token, `handle_reply_upload` saves the file, sets request status to `RECEIVED`, updates `RowState`, and creates a `phase="CASE"` Job resuming only that row.
6. When comparing syllabus, `compare_syllabus_for_row` checks for AUD catalog CLOs. If missing, it halts with `AUD_SYLLABUS_MISSING`. Otherwise, citations are verified by `run_referee_check`, stripping invalid citations and downgrading if none remain.
7. The officer accepts or rejects via `officer_review_syllabus`. On accept with `add_to_mapping`, `add_mapping_row` inserts a versioned entry into `course_mappings`.

## 9. Known Gaps & Assumptions
- Official AUD undergraduate catalog `catalog/aud_undergrad_2026_2027/courses.json` contains course descriptions only, with `outcomes: []`. As mandated by the specification, comparison against courses lacking CLOs marks the status as `AUD_SYLLABUS_MISSING` and stops without fabricating outcomes.
- In production, real SMTP sending requires setting `EMAIL_SENDING=true` in `.env` along with authorized sender credentials and allowlist configurations.
